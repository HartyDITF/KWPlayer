# Промпт: полная реализация интерфейса и функций KW Player

## РОЛЬ И КОНТЕКСТ
Ты Android-разработчик. Проект: KW Player (Kotlin, Jetpack Compose, Material 3, Media3, Glance), репозиторий hartyditf/kwplayer, пакет fyi.kiyori.modernmediaplayer. Сначала изучи существующий код (тема: core/design/theme/KwColors.kt и KwTheme.kt; скины: feature/themes/ThemesDialog.kt; настройки: data/settings/KwSettingsRepository.kt; сервис: PlaybackService.kt; видеоплеер: feature/video/VideoPlayerScreen.kt; виджет: widget/PlayerGlanceWidget.kt) и расширяй его, не переписывая с нуля и не создавая дубли. Если файла нет, найди аналог.

Цель: приложение, которое копирует VLC (вкладки, функции) и YouTube (вид ленты, боковые поля плеера, настройки в плеере), с музыкой в стиле YouTube Music/Spotify, семью скинами, виджетами папок и загрузкой по ссылке с докачкой.

## ПОРЯДОК РАБОТЫ
Делай по этапам, после каждого сборка и проверка, что приложение не падает: 1) тема и скины, 2) каркас и навигация, 3) видео, 4) аудио и полный плеер, 5) обзор, плейлист, «Ещё», шторка оформления, 6) видеоплеер, 7) сервис, фон, PiP, звук, 8) загрузки, 9) виджеты, 10) по желанию Rust-модуль. В конце каждого этапа кратко напиши, что сделано и что не проверено.

## ОБЩИЕ ПРАВИЛА
- Весь текст на русском, строки в strings.xml.
- Цели нажатия не меньше 48dp, у иконок без текста contentDescription, контраст текста не ниже 4,5:1.
- Цвета, радиусы и шрифт только из объекта KwSkin, никаких жёстких цветов в экранах.
- Тяжёлая работа (сканирование папок, миниатюры, база) вне главного потока; списки только Lazy* со стабильными key.
- Состояние «играет» хранится в одном месте: MediaSession.
- minSdk 26. Если разрешение или файл недоступны, показывай пустое состояние, а не падай.
- Правило надёжности: никаких вылетов, зависаний, утечек; в onStop и onPause ничего тяжёлого; состояние переживает поворот и убийство процесса.

### 9. Загрузка по ссылке
Поле URL (48dp, скругление 12dp) + «Найти» (accent). Карточка найденного: постер 64×92dp, название, «Фильм · 2 ч 04 мин», «Найдено доступных вариантов: 5 качеств, 4 озвучки». «КАЧЕСТВО»: плитки 360p, 480p, 720p, 1080p, 1080p Ultra с «≈ размер» (выбранная accent); если заявленное качество выше реального потока, жёлтая плашка «Источник заявляет 1080p Ultra, по факту отдаёт 1080p. Проверка идёт по реальному потоку, размер уточнён». «ОЗВУЧКА»: radio-карточки (Дубляж, Оригинал + субтитры, Закадровый двухголосый, Авторский одноголосый). Переключатель «Скачать субтитры». Серии: «С серии» / «По серию» (1–12, степперы − и +). Кнопка «Скачать N серий · ≈ размер». «Загрузки»: чип «Только Wi-Fi», плашка статуса сети, список: название, мета, прогресс-бар 6dp, статус, пауза/продолжить, у готовых «Открыть».
Движок: Media3 DownloadManager + DownloadService (foregroundServiceType=dataSync, разрешения FOREGROUND_SERVICE и FOREGROUND_SERVICE_DATA_SYNC, intent-filter RESTART, Scheduler), SimpleCache с NoOpCacheEvictor, requirements по сети. Для mp4 докачка по HTTP Range (проверять ответ 206; при 200 честно сообщать «докачка недоступна»), для HLS догружаются недостающие сегменты. Пропала сеть: статус «Нет сети. Пауза на 11% (… из …). Продолжу с этого места», при возврате загрузка идёт с сохранённого места, не с 0, в том числе после перезапуска приложения. Устаревшая ссылка (403/410): заново разобрать страницу, получить свежую ссылку и продолжить с того же смещения. Прогресс пишется после каждого блока. При первом открытии экрана показать предупреждение: за скачиваемый контент отвечает пользователь.

1) «Папка видео» (от 4×2): шапка «<Папка> · <Источник>», счётчик файлов, кнопка настройки. Виды: «Сетка» (4 превью, подпись внизу), «Список» (3 строки: миниатюра 52×30, название, play), «Карточка» (один большой кадр, круглая play, название). Тап открывает видео в приложении (PendingIntent на плеер с uri). 2) «Учёба»: заголовок и 3 строки с play. 3) «Музыка»: обложка 44dp, название, исполнитель, назад / пауза / вперёд (управляют MediaSession).
Экран настройки (configuration activity, android:configure, reconfigurable): список папок (radio), «Добавить другую папку (системный выбор)» с постоянным разрешением, «ВИД» (Сетка / Список / Карточка), «ЧТО ПОКАЗЫВАТЬ» (Недавние / Новые / Не досмотрены), «ЦВЕТ» (Системный: цвета обоев Android 12+; Тема приложения: выбранный скин; Прозрачный: тёмная подложка 42%), «Готово, добавить виджет». Настройки хранятся на каждый appWidgetId. Обновление не чаще раза в 15 минут и при смене папки, миниатюры из кэша.

## ПЛАТФОРМА
- PlaybackService: наследник MediaSessionService с MediaLibrarySession, foregroundServiceType=mediaPlayback, уведомление с обложкой и кнопками (экран блокировки управляется системно). Фон работает только при включённом «Воспроизведение в фоне», иначе пауза при уходе с экрана.
- Android 17: фоновый звук без видимого экрана или foreground-сервиса блокируется молча, поэтому сервис должен быть foreground. Сервис останавливается при конце воспроизведения, AUDIOFOCUS_LOSS, паузе из системного управления и неисправимой ошибке; стартует заново только по явному «Играть»; переживает короткие сбои (буферизация, временная потеря фокуса) до 10 минут. onTaskRemoved сохраняет позицию и очередь.
- Звук: пауза при отключении наушников (handleAudioBecomingNoisy); переключатель «Динамик / Наушники» через предпочитаемое аудиоустройство плеера с запасным вариантом: системный переключатель вывода. Поведение зависит от устройства, проверить на реальных телефонах.
- Цвета системы: Material You на API 31+ из обоев, светлая/тёмная тема следует системной.
- Тест: adb shell cmd audio set-enable-hardening throw. Проверить: фон при выключенном экране, блокировка, PiP, поворот, убийство процесса, отключение наушников, звонок во время игры.

## RUST (по желанию, только этот объём)
Целиком переписывать приложение на Rust не нужно: интерфейс остаётся на Compose, декодирование на Media3. Rust-модуль через UniFFI и cargo-ndk только для движка докачки (Range, параллельные потоки, проверка целостности, сохранение смещения) и индекса медиатеки (сканирование, поиск). За общим интерфейсом на Kotlin, чтобы можно было переключать реализации. Сначала реализуй всё на Kotlin, затем замерь и переноси в Rust только то, что реально медленное.

## ПРИЁМКА
Приложение собирается без предупреждений об устаревшем коде; нет вылетов при повороте, убийстве процесса, потере сети и отзыве разрешений; прокрутка лент 60 fps; смена скина мгновенно перекрашивает все экраны; названия и обложки отображаются везде корректно; всё, что не удалось проверить без устройства, перечислено в итоговом отчёте.
